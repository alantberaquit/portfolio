Troubleshooting Guides

Open only the issue you need. Each guide prioritizes the fastest safe checks first.

Typical symptoms: invalid login, repeated authentication prompt, locked account, or password reset without restored access.

1. Confirm credentialsVerify username/email and rule out saved stale credentials.
2. Check account stateConfirm the account is active, not locked, and not pending activation.
3. Retry private sessionUse an incognito/private window to rule out stale cookies.
4. Check identity providerIf SSO is used, confirm the user is assigned correctly.

Typical symptoms: delayed page loads, spinning indicators, timeouts, or unusually slow save/search actions.

1. Check scopeDetermine whether the issue affects one user, one page, or the entire application.
2. Check networkConfirm the user has a stable connection and no active VPN/proxy issue.
3. Compare browsersTry a supported alternate browser to isolate local browser impact.
4. Check service statusReview known degradation or active incidents before escalating.

Typical symptoms: records remain outdated, imports appear incomplete, or connected-system changes do not arrive.

1. Confirm sync windowCheck whether the integration is real-time or scheduled.
2. Verify source dataConfirm the source record was saved successfully and has required fields.
3. Check integration statusReview error logs, failed jobs, or health indicators if available.
4. Avoid duplicate retriesDo not repeatedly resubmit if duplicate records could be created.

Typical symptoms: missing buttons, overlapping text, blank panels, or controls in the wrong position.

1. Refresh safelyReload after confirming no unsaved work will be lost.
2. Clear local issueTry private browsing or clear site-specific cache if permitted.
3. Confirm supportCheck whether the browser/version is officially supported.
4. Compare deviceTest another supported browser or device to confirm whether the issue is local.

Typical symptoms: user can sign in but cannot access a page, edit a record, run an action, or view required data.

1. Identify required actionConfirm exactly what page, record, or operation is blocked.
2. Check assigned roleCompare the user’s role with a known user who can complete the task.
3. Confirm recent changesCheck whether role, team, or account permissions recently changed.
4. Escalate access changesDo not grant elevated access unless your role authorizes it.

Escalation Guide

Stop troubleshooting when impact or risk exceeds frontline support boundaries.

Continue troubleshooting

Stay with the issue when impact is limited and the checks are low-risk.

  • Single user affected
  • Known/common symptom
  • No data-loss risk
  • Safe reversible checks available

Prepare escalation

Gather evidence and hand off when the issue persists after supported checks.

  • Multiple users affected
  • Repeated failure after known fixes
  • Integration or permission change needed
  • Root cause remains unclear

Escalate immediately

Do not continue experimentation when the issue could create wider risk.

  • Possible security incident
  • Data corruption or loss
  • Business-critical outage
  • Production-wide access failure
